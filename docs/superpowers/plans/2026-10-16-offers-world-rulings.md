# Offers world: rulings made during implementation

Decisions taken by the controller while executing docs/superpowers/plans/2026-10-16-offers-world.md (each: what was decided, why, what it costs if wrong). Real client names never appear here.

- Ruling R1: offer-key letter suffix only when followed by end, whitespace, `_`, `.` or `)` (`-[A-Z](?=$|[\s_.)])`); add test `("3006904-CPL01-Q01_.pdf", "3006904")` — real IPSO file names — wrong: a rare `1106033-A`-style key could be missed.
- Ruling R2: archive key matched anywhere with a non-alphanumeric before it (`(?<![A-Za-z0-9])[BFE]-(\d{6})(?!\d)`) — file names carry it mid-name — wrong: low.
- Ruling R3: doc_type `offer` also for a file directly in the offer folder whose name contains the offer key (archive layout) — spec's archive offers must be read — wrong: low.
- Ruling R4: PriceLine.position is 1-based in document order — corrections CSV uses positions people read — wrong: off-by-one in corrections.
- Ruling R5: the owner of a duplicated offer key is the folder with the most indexed documents of that key, ties by path alphabetical — spec says "first folder kept"; most-documents is the meaningful "first" — wrong: a client with fewer docs might be the true owner (review.csv lists it).
- Ruling R6: T5 fixture dates: 00 = 10.02.2020, 01 (+DE) = 03.03.2020, 02 = 20.04.2020, 03 (both variants) = 14.05.2020 — makes the plan's own assertions consistent — wrong: none (test data).

- Ruling R9: T7 list_offers test checks that a line starts with `3001234 · ACME Foods` (any line), not the first — newest-first order is correct, the plan's assertion was not — wrong: none.
- Ruling R10: in `;`-tables, `;` and newlines inside text cells become `,` and space — keeps the table parseable — wrong: cosmetic.
- Ruling R11: classify order = discount > option (option word in the item's first label line) > machine (models_in finds a family/model in the item's first label line) > service (whole-word service words; emballage/verpackung/packing removed; transport\b) > machine words > other — the plan's order classes packaging machines as services, which defeats the price charts — wrong: an installation line naming the machine first ("Paloma 3R installation") becomes machine; sum check unaffected.
- Ruling R12: label hygiene: all-caps label lines without digits/amounts are headings (skipped); label lines right after a closed block that start with -, •, *, a lowercase letter, or including/inkl/einschliesslich/y compris/comprenant are the previous item's description (appended to its text); a page's first line holding an offer word + offer number, or Page/Seite n, is a running header (skipped) — the plan's block algorithm glued them onto the next item — wrong: a real item starting lowercase is merged into the previous one; sums still checked.
- Ruling R13: priced lines after the net total are still returned but force sum_ok False (revision goes to the model / low confidence) — precision first; the plan returned them as if checked — wrong: in-page variants get low confidence instead of high.
- Ruling R14: price_pages keeps scanning when the first candidate run has no net total and uses the first later run that ends in one; else the first run — a cover letter with a price must not hide the real section — wrong: none known.
- Ruling R15: chat_json sets num_ctx = clamp(len(prompt)//3 + num_predict, 8192, 16384) and keep_alive "10m"; the instructions go after the page text (short role line first); when the answer's prompt_eval_count reaches num_ctx - num_predict the call raises VisionError("prompt cut") — the plan's fixed options let Ollama cut the instructions silently — wrong: 16k context costs VRAM on the A4000 next to gemma4:12b (pages beyond it are then refused, not misread).
- Ruling R16: grounding — every amount and total returned by the model must be found among the amounts/numbers printed in the pages sent (same parse_number normalisation); any ungrounded value forces sum_ok False — a model-computed total equal to its own lines would otherwise read as checked — wrong: a model that normalises a number differently gets low confidence.
- Ruling R17: documents with status other than ok (no_text, error, empty) and offers left without candidates are listed: revision rows with read_by 'none', confidence 'none' and a note ('no text (status no_text)', 'file error: …'); an owner folder without offer documents falls back to the duplicate folder that has some — spec "Failures" says every revision is listed with its reason; the plan's status='ok' filter dropped them — wrong: none.
