- Ruling R12: label hygiene: all-caps label lines without digits/amounts are headings (skipped); label lines right after a closed block that start with -, •, *, a lowercase letter, or including/inkl/einschliesslich/y compris/comprenant are the previous item's description (appended to its text); a page's first line holding an offer word + offer number, or Page/Seite n, is a running header (skipped) — the plan's block algorithm glued them onto the next item — wrong: a real item starting lowercase is merged into the previous one; sums still checked.

- Ruling R14: price_pages keeps scanning when the first candidate run has no net total and uses the first later run that ends in one; else the first run — a cover letter with a price must not hide the real section — wrong: none known.
- Ruling R15: chat_json sets num_ctx = clamp(len(prompt)//3 + num_predict, 8192, 16384) and keep_alive "10m"; the instructions go after the page text (short role line first); when the answer's prompt_eval_count reaches num_ctx - num_predict the call raises VisionError("prompt cut") — the plan's fixed options let Ollama cut the instructions silently — wrong: 16k context costs VRAM on the A4000 next to gemma4:12b (pages beyond it are then refused, not misread).

- Ruling R17: documents with status other than ok (no_text, error, empty) and offers left without candidates are listed: revision rows with read_by 'none', confidence 'none' and a note ('no text (status no_text)', 'file error: …'); an owner folder without offer documents falls back to the duplicate folder that has some — spec "Failures" says every revision is listed with its reason; the plan's status='ok' filter dropped them — wrong: none.
